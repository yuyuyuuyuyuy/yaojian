# 药鉴 · MVP 迭代计划（S8 产出）

> 版本 1.0 ｜ 2026-09-17 ｜ 0→1 流程 S8（MVP 范围与迭代节奏）执行产出
>
> **文档定位**：把 PRD 的 V0.1 拆成 4 个可执行迭代。每个迭代结束=**可运行、可验证的产品增量**——验收标准过了才算 Done，不是「代码写完了」。
>
> **范围**：V0.1 = F0 会话历史 + F1 资料入库 + F2 多库问答 + F3 引用核对 + F4 双防线 + F7b 多轮改写 + F13 备份迁移（PRD 第六章）。
>
> **迭代划分原则**：**先纵切骨架，再横切功能**——I1 先把产品「端到端跑通」（窗口→后端→前端→问答占位），之后每个迭代给这条主线加厚一层。反对先做完所有前端再做后端（横切）：那是三周看不到任何东西的路线。

---

## I1 骨架：能跑起来的空产品

**目标**：双击启动 → 出现产品窗口（侧边栏/聊天区/设置页布局）→ 设置可保存 → 干净退出。端到端管线打通（先不接真功能）。

**任务清单**：
1. 项目结构：config（数据目录/默认设置/版本）+ main（起 Flask 线程+开 pywebview 窗口）；
2. 后端路由壳：/api/health、/api/settings GET/POST（白名单字段校验）；
3. 前端三区布局：侧边栏（品牌 logo/知识库列表占位/新建按钮）、聊天区（消息列表/输入框占位）、设置页（API Key/模型/外观/费用说明）；
4. 首次启动引导（5 步向导，可跳过，设置页可重看）；
5. 深色模式（三态：跟随系统/浅色/深色，持久化+防启动闪白）；
6. 断网降级基础（启动不依赖网络；网络功能占位提示）。

**验收标准**：
- 双击启动出现窗口，无 Python 环境要求（打包版验证）；
- /api/health 返回版本号；设置保存后重启保持；
- 关窗干净退出（无残留进程）；
- 深色模式三态即时生效且重启保持。

**依赖**：无（全新开始）。**风险**：WebView2 缺失（启动检测+提示下载）。

## I2 RAG 核心：资料进得去、查得出来

**目标**：建知识库 → 导入资料（内置 QC 语料+用户文件）→ 后台建索引 → 检索命中。**本迭代验收不依赖 LLM 对话**（只花 embedding 小钱，可反复跑）。

**任务清单**：
1. 内置 QC 语料（10 大类文档随包分发）+ 首次启动自动建索引；
2. 解析器：txt（自动测编码，按行）/pdf（按自然段，扫描版检测）/docx/pptx（混合提取：文本层+图片页 OCR 兜底）；
3. 向量化+索引：embed 批量接口、sqlite-vec 建库/插入/KNN 查询、增量索引三行为（md5 未变跳过/变更重建/删除移除，F1 验收④）、每库 threading.Lock（并发控制）；
4. 知识库管理：新建/导入（文件+文件夹）/删除（二次确认+明示后果，F1 验收⑥）/文档列表；
5. 召回调试视图：输入问题看 top-K 命中与分数（设置页第二标签）；
6. 语料统计台账：文件明细/块数/未入库清单（ingest_stats 持久化）。

**验收标准**：
- 内置库首建索引秒级完成；20 题验收集检索**命中率 ≥90%**（tests 检索实验，免费反复跑）；
- 导入课件 PDF/PPT 后检索命中其内容；图片型 PPT 页 OCR 兜底成功；
- 增量索引：重复导入零新增费用；修改文件后重建该文件；删除后索引移除；
- 导入失败文件有清单与原因；并发导入不报锁错误。

**依赖**：I1。**风险**：sqlite-vec 轮子问题（回退 numpy）；OCR 兜底失败不阻塞入库。

## I3 对话核心：问得出来、答得可信

**目标**：聊天问答端到端——流式输出、引用徽章展开、双防线、多轮改写。**本迭代 Done 的定义=金标评测三关通过**。

**任务清单**：
1. 问答编排：检索 → 命中判定（零命中=规则拒答不调 LLM；弱相关=缩小范围/明示，F4 验收③）→ 铁律提示词+引用资料 → LLM 流式生成；
2. 引用链路：回答中 [n] 徽章渲染 → 点击定位展开原文（库名/文件名/相似度/页码）→「此引用有问题」反馈按钮（F3 验收⑤）→ 流式中断资源释放（停止=后端中止 LLM 流+半截补存）；
3. 多轮：指代改写（A7b，检索前补全指代）+ 上下文有界窗口（最近 N 轮，F2 验收⑤）；
4. 对话操作：复制/停止/重新生成；新对话/清空；
5. 模型变更管理基础：变更日志+变更后提示跑金标评测（F4⑤ 的基础件）。

**验收标准（=金标评测三关）**：
- 20 道单题：引用溯源全对、要点覆盖率 ≥60%；
- 3 组多轮追问：指代改写正确，逐轮溯源通过；
- 2 道拒答题：输出「资料中未找到相关内容」；
- 金标报告自动生成+与上次对比（F11 骨架）。

**依赖**：I2。**风险**：模型服从度不足 → 提示词铁律调优；流式渲染异常 → 降级非流式。

## I4 数据完整与交付：用户资产能留存、能带走

**目标**：会话历史、导出、备份迁移、打包分发——用户开始积累的数据不丢、能带走，产品能交付给真实用户。

**任务清单**：
1. 会话历史（F0）：列表（标题自动取首问前 N 字可改名/时间/知识库范围）/载入继续聊/删除；
2. 导出（F3 验收③）：对话导出 Markdown/Word（引用内联；公式保真——Markdown 保留 LaTeX、Word Unicode 或图片）；
3. 备份迁移（F13）：全量数据包导出（SQLite backup API 在线备份+kbs 打包）/覆盖式恢复（确认提示）/不含敏感凭据；
4. 打包分发：PyInstaller onedir（collect_all 清单固化）+ zip + 使用说明 +《隐私说明》一页纸 + logo；
5. 更新检查：启动异步检查 GitHub Releases（超时静默/纯提示）；
6. 日志与诊断：日志写数据目录（滚动限量）。

**验收标准**：
- 历史会话载入/删除正确；导出 Word 打开正常、引用内联、公式不乱码；
- 备份包在新目录恢复后功能完整可用（隔离环境验证）；恢复确认提示生效；
- **解压即用新机冒烟测试**：无 Python 环境机器跑通问答+引用+导出全链路；
- 使用说明与隐私说明随包分发。

**依赖**：I3。**风险**：杀软误报（使用说明披露）；打包遗漏（冒烟测试兜底）。

## PM 知识点卡

**卡 1 ｜ 纵切 vs 横切（先跑通主线，再逐层加厚）**
- 概念：横切=按层做（先做完前端、再做后端、再做数据）——每层都是半成品，三周看不到能用的东西；纵切=按功能链做（一条端到端链路先走通，再加下一条）——每个迭代结束都有能跑、能看、能验证的增量。
- 业内做法：第一个迭代永远做「骨架纵切」：用户能启动、能完成一个最小闭环（哪怕答案是假的），让所有集成风险提前暴露。
- 示例：本计划 I1 就是骨架纵切（窗口→后端→前端→设置全通），I2/I3 在骨架上加厚。如果横切，sqlite-vec 打包问题和 SSE 流式问题会挤在最后一周一起爆——纵切让它们在 I2/I3 各自暴露、各自消化。

**卡 2 ｜ Done 的定义 = 验收标准通过，不是「代码写完了」**
- 概念：迭代的完成定义（Definition of Done）必须写成可验证的验收标准；「写完了但没验」=没做完。
- 业内做法：验收标准在迭代开始前写好（写标准的过程就是逼自己想清楚「这个迭代到底要什么」）；验收标准要可重复执行（脚本化优先）。
- 示例：I3 的 Done 定义=金标评测三关通过——不是「问答功能代码完成」。代码写完金标不过，迭代不算完；金标过了才算。

**卡 3 ｜ 把闸门放进迭代（质量内建，而非事后补测）**
- 概念：质量闸门（金标评测/冒烟测试）如果是「发布前的最后一步」，它就会被压缩和跳过；把它变成某个迭代的 Done 定义，它就成了迭代的一部分。
- 业内做法：每个迭代的验收里含质量项；发布=各迭代验收之和，不额外加「大测试」。
- 示例：本计划把金标三关设为 I3 的 Done、把新机冒烟设为 I4 的 Done——发布前总验收只是「重跑一遍各闸门+专项双防线」，没有「临时补测」的慌张。
