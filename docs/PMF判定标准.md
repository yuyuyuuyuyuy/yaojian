# 药鉴 · PMF 判定标准（S13 机制设计）

> 版本 1.0 ｜ 2026-09-17 ｜ 0→1 流程 S13（PMF 判定）机制设计产出
>
> **文档定位**：0→1 的「1」的判定标准——产品是否被市场**真正需要**。判定执行依赖 S11 真实用户测试数据，本文档先把标准定死，数据一到直接对照判定，不带感情色彩。

---

## 第一章 PMF 是什么、为什么是决策门

**PMF（Product-Market Fit，产品市场契合度）**：产品解决了目标用户愿意付费/持续使用的真实问题。反义词是「我做的产品我很喜欢」——发明者偏好不等于市场需要。

**为什么必须有个判定门**：很多产品死在「以为有需求但其实没有」。PMF 判定把「感觉产品不错」变成「证据证明产品被需要」——三种去向：**GO（加大投入）/ Pivot（转型）/ 止损**。对药鉴来说，判定结果直接决定：继续投入开发与增长、调整定位（如主攻 C 群）、还是将其定位为作品集项目（停止增长投入）。

**业界参照（Sean Ellis 40% 法则）**：问用户「如果产品明天消失，你会非常失望吗？」——≥40% 回答「非常失望」即初步 PMF 信号（该法则来自《Hacking Growth》作者 Sean Ellis 的创业实践）。

## 第三章 三结论判定规则（量化门槛）

| 结论 | 门槛（全部满足才成立） | 后续动作 |
|---|---|---|
| **GO（加大投入）** | ①H1、H2 全部 ✅；②P1 假设至少 3 条 ✅（其中 H7 或 H10 至少一条 ✅——学习闭环的价值必须被验证）；③H8 ≥50% 或 C 群付费显著；④推荐分 ≥60% 给 ≥7 分 | 进入增长阶段（S14 发布合规 → S15 增长获客 → S16 留存运营）；F10 考得上启动（若 H11 ✅） |
| **Pivot（转型）** | ①H1/H2 至少一条 ✅（核心价值部分成立）；②但 GO 的②③④中有两条不满足 | 按证据调整：例——若 C 群假设全过而 A 群全挂 → 定位主攻考研人群；若 H7 挂 H10 过 → 弱化笔记强化卡片；调整后重新小规模验证 |
| **止损（停止增长投入）** | ①H1、H2 全部 ❌；②H8 <30%；③推荐分 <60% 给 ≥7 分 | 产品保留为作品集项目（功能完整、文档齐全仍是优质求职作品）；停止增长与商业化投入；不再招测试者 |

**灰色地带规则**：不满足任何一档完整门槛时——回看证据最弱的环节补一轮小样本验证（如 3 人定向补测），再判定；**禁止在灰色地带直接宣布 GO**。

## 第四章 判定执行流程

1. **数据回收**（S11）：问卷 Excel + 各测试者埋点导出 JSON + 观察记录汇总；
2. **聚合**：Claude 按 2.1~2.4 逐条填表（每条附原始数据引用，可复核）；
3. **判定**：对照第三章门槛得出三结论之一；
4. **记录**：判定结论+全部证据写入 决策记录.md（新决策编号）+ 需求调研文档第四章（假设验证结论回填）——**H1~H11 的判定结果同时就是需求调研文档的假设验证闭环**；
5. **输出**：用户测试报告（含判定表、观察项处置、设计修正清单）作为项目证明材料；一页纸/落地页的关键数据同步更新。

## 第五章 PM 知识点卡

**卡 1 ｜ PMF 判定：把「感觉」换成「证据」**
- 概念：PMF 不是心情，是可判定的状态——前提是**判定标准在收集数据之前定死**（本文档正在做的事）。事后定标准必然「数据迁就结论」。
- 业内做法：标准先行、三结论（GO/Pivot/止损）都有明确门槛、灰色地带禁止直接 GO；Sean Ellis 40% 法则是最流行的快速信号。
- 示例：第三章门槛是在 S11 执行前写死的——测试者一个都没招募，门槛已经在这里等着数据。这样数据回收后谁也无法「灵活解释」结果。

**卡 2 ｜ Pivot（转型）不是失败，是不带感情用事**
- 概念：创业领域的共识——「转型」是常态而非例外（Twitter 前身是播客平台、Instagram 前身是签到应用）。Pivot 的定义=保留已验证的资产，调整未验证的假设。
- 业内做法：转型决策基于「哪部分假设过了、哪部分挂了」——挂了的砍、过了的加注，而不是全盘推倒。
- 示例：若判定为 Pivot 且证据是「C 群假设全过、A 群全挂」——动作是定位主攻考研人群、营销资源全部转向考研渠道，而产品功能（学习闭环）完全保留。这就是「证据导向的转型」。

**卡 3 ｜ 止损也是成功：沉没成本不是继续的理由**
- 概念：PM 最贵的错误是「已经投入这么多，不能停」。已投入的成本（沉没成本）不影响未来决策——未来只看「继续投入的预期收益」。
- 业内做法：止损标准前置（如 H8 <30% 且核心假设全挂）；止损动作=停止增长投入，但保留资产（代码/文档/数据可复用到下个项目）。
- 示例：即便走到止损，药鉴仍是完整的作品集项目（16 功能+金标 25/25+全套 0→1 文档+真实测试数据）——止损意味着「不再投入增长」，不是「成果作废」。
