# 药鉴 · 技术架构评审（S7 产出）

> 版本 1.0 ｜ 2026-09-17 ｜ 0→1 流程 S7（技术架构评审）执行产出
>
> **文档定位**：立项后、开发前——以企业级技术评审视角从零确定架构与选型。评审铁律：**技术选型服务于产品目标与约束，而非追求新潮**；每个选型必须写明风险与回退路径。
>
> **复盘说明**：本流程为 0→1 复盘式重跑（产品实际已发布 v0.3.0，实现状态见 决策记录.md）。
>
> **产品约束（来自 PRD）**：本地私有（无服务器）；数据在本机；校园网不稳定；目标用户设备跨度大（4GB 千元机~旗舰）；按量低成本；Windows 首发、Mac 观察项；开发协作=产品发起人（非程序员）+ AI。

## 第一章 总体架构设计

```
┌──────────────────────────────────────────────┐
│ 桌面壳 pywebview（Windows 原生窗口，WebView2）   │
│  ┌────────────────────────────────────────┐  │
│  │ 前端：纯静态 HTML/CSS/JS（无构建无 CDN）   │  │
│  │  问答流式渲染 / 引用徽章展开 / 知识库管理    │  │
│  └────────────────────────────────────────┘  │
├──────────────────────────────────────────────┤
│ 本地后端：Flask 线程（localhost，无外网暴露）     │
│  server（路由壳）→ chat（编排）→ search（检索）  │
│  ingest（索引）→ store（数据）→ export（导出）   │
│  embeddings / ocr / parser（可独立替换的模块）   │
├──────────────────────────────────────────────┤
│ 本地存储：SQLite（chat.db：对话/笔记/事件表）      │
│  + kbs/<id>/（docs 源文件 + index.sqlite 向量库） │
├──────────────────────────────────────────────┤
│ 外部 API：阿里云百炼（OpenAI 兼容协议）            │
│  qwen-plus（对话/改写/裁判）· text-embedding-v4  │
│  （嵌入）· qwen-vl 系列（OCR）                    │
└──────────────────────────────────────────────┘
```

**核心数据流（一次问答）**：提问 →（多轮时）指代改写 → 查询向量化 → 向量 KNN 检索（top_k、阈值）→ 命中判定 → 零命中=规则拒答（不调 LLM）/ 命中=铁律提示词+引用资料 → LLM 流式生成 → 前端渲染 [n] 徽章 → 用户点击展开原文核对。

**流式中断的资源释放**：用户点「停止」=前端 AbortController 断开 → **后端必须捕获断开信号（GeneratorExit）立即中止 LLM 流调用**——能省多少 token 省多少，线程及时释放；已生成部分补存入库保持历史问答配对。

**更新检查（PRD 交付物承接）**：启动后**异步**检查 GitHub Releases 版本号（超时 5 秒；**失败静默降级，不弹错不阻塞启动**——校园网不稳）；本地版本较旧则提示+跳转下载页；纯提示，不下载不安装（本地私有定位：更新必须用户主动）。

**日志与诊断（F15 配套）**：运行日志写数据目录（滚动、限量）；意见反馈弹窗可选「一并导出诊断日志」——非程序员用户报障「它不好使了」时开发者有定位依据（隐私提示：日志含操作记录、不含对话内容）。

## 第二章 关键选型评审表

> 每项：候选对比 → 选定 → 理由（对应产品约束）→ 风险与回退。

### 2.1 桌面框架：**pywebview**（候选：Electron / Tauri）

| 候选 | 优劣 |
|---|---|
| **pywebview** ✅ | 一门 Python 贯穿前后端；复用 RAG 全部经验；打包体积小（~150MB）；新手可维护 |
| Electron | 前端生态最强，但 RAG 需 JS 重写、打包 200~300MB、双语言栈 |
| Tauri | 体积最小，但 Rust 技术栈对非程序员发起人是死路 |

- 理由：约束「发起人非程序员+AI 协作」→ 语言栈越少越好；约束「千元机」→ 体积越小越好。
- 风险：依赖系统 WebView2 运行时 → 回退=启动时检测缺失弹中文提示+官方下载链接（PRD 交付物已定）。
- 端口冲突：Flask 固定端口被其他程序占用 → 启动失败 → **回退=端口被占自动换端口重试**（前端从启动信息获取实际端口）。

### 2.2 后端 HTTP：**Flask + werkzeug 线程**（候选：FastAPI / pywebview 内置 server）

- 理由：单机 localhost 无并发压力，werkzeug 自带服务器足够；SSE 流式用生成器即可；打包无痛。
- 风险：werkzeug 非生产服务器 → 无关紧要（单用户本机）；**技术坑**：必须禁用 Flask 内置 /static 路由（自定义静态路由被抢先匹配导致 404）。

### 2.3 向量存储：**sqlite-vec**（候选：ChromaDB / numpy 暴力检索）

| 候选 | 优劣 |
|---|---|
| **sqlite-vec** ✅ | 单 DLL 扩展，一个 SQLite 文件装下块+向量+文件哈希；无重型依赖树 |
| ChromaDB | 生态成熟，但依赖树沉重、PyInstaller 打包公认痛点 |
| numpy 暴力检索 | 零依赖，语料数千块时检索毫秒级——**回退方案** |

- 回退设计：向量库接口抽象为 5 个函数（建库/插入/查询/复制/统计），换 numpy 一天内完成。
- 已知坑（写进开发注意事项）：KNN 在 JOIN 场景必须显式 `k = ?` 约束；查询向量必须归一化后 MATCH。

### 2.4 嵌入模型：**百炼 text-embedding-v4**（候选：本地 fastembed/bge-m3）

- 理由：约束「校园网不稳」→ 零模型下载（本地方案需从 HuggingFace 下载，校园网经常失败）；与 LLM 同 Key 同账单。
- 隐私说明：问答时文档片段本就会发送至 LLM，本地向量化只解决一半隐私问题——PRD 已明示。
- 回退设计：`embeddings.py` 只暴露 `embed()` 一个接口，换本地模型只改一个文件。
- **A8 联动（维度迁移风险）**：text-embedding-v4=1024 维；换其他嵌入模型维度不同 → 全部索引需重建（见第三章）。

### 2.5 对话模型：**百炼 qwen-plus**（温度 0 固定）

- 用途三合一：问答生成、多轮指代改写（A7b）、金标评测裁判（LLM-as-judge）。
- 约束：温度 0 不可由用户调整（防幻觉铁律）；「更贵的模型=更好」不成立（CCI：越强越不肯拒答）→ 模型变更必须重跑金标评测（F4⑤）。

### 2.6 OCR 模型：**qwen-vl 系列**（默认 qwen3-vl-plus；设置可换）

- 手写/公式识别需要多模态模型；印刷体可用更省的 qwen-vl-ocr-latest。
- 设置页可换（A8）：手写最强=qwen-vl-max-latest；印刷体最省=qwen-vl-ocr-latest。

### 2.7 前端：**纯静态 HTML/CSS/JS，无构建无 CDN**

- 理由：不装 Node、不编译（发起人可维护）；校园网不可靠 → 不引 CDN，Markdown 渲染自写迷你渲染器。
- 文件上传用原生 `<input type=file>` + `webkitdirectory` 走 HTTP（不依赖桌面壳原生对话框，浏览器中同样可测）。

### 2.8 打包分发：**PyInstaller onedir + zip**（候选：onefile / 安装器）

- 理由：onefile 启动慢、杀软误报率显著更高；未签名安装器同样触发 SmartScreen，多一层工具链无收益。
- 用户数据全部 `%APPDATA%\药鉴\`（索引可再生，永不作为唯一数据源——程序目录只放只读内容）。

### 2.9 数据存储：**SQLite + 文件系统**

- chat.db：会话/消息/笔记/事件（埋点）四类表；kbs/<id>/：docs 源文件 + index.sqlite 向量库 + ingest_stats.json 台账。
- 增量索引：文件 md5 哈希——未变跳过（零重复费用）、变更重建、删除移除（PRD F1 验收④）。
- **并发控制（评审补强）**：后台建索引与前台提问并发读写 SQLite——**每库一个 `threading.Lock`**，索引构建期间提问排队；构建期间新增的变更请求记入待处理队列，本轮结束后补跑一次增量（幂等）。防「database is locked」事故。
- **备份一致性（F13 承接）**：数据包导出时数据库可能正在写——chat.db 用 **SQLite 在线备份 API（`sqlite3.Connection.backup`）** 保证快照一致，禁止直接复制文件；kbs 目录直接打包。

## 第三章 A8 多模型支持的设计影响（PRD 新增需求的架构承接）

### 3.1 服务商抽象层

- settings 增加三组独立配置：**对话模型**（base_url/api_key/model）、**嵌入模型**（同）、**OCR 模型**（同）——互相独立互不影响；
- 协议=OpenAI 兼容（DeepSeek/智谱/Kimi/硅基流动/Ollama 全部兼容，行业事实标准）；
- 前端设置页增加「服务商」区：预设几家常用服务商下拉+自定义 Base URL 输入框。

### 3.2 三类模型的切换代价（不对称，必须向用户讲清）

| 模型类型 | 切换代价 | 说明 |
|---|---|---|
| 对话模型 | 零代价 | 无持久依赖，即换即用（但触发 F4⑤：换后跑金标评测） |
| OCR 模型 | 零代价 | 同上 |
| **嵌入模型** | **全部索引重建** | 向量维度不同（1024 vs 768/2048），旧索引全部失效——切换时检测维度不匹配 → 明确提示「切换嵌入模型需要重建全部索引（预计耗时与费用 X）」→ 用户确认后一键重建 |

### 3.3 模型变更管理流程（F4⑤ 的技术落地）

- settings 变更模型时：写入变更日志（模型 A→模型 B、日期、版本）；
- 变更后首次启动：提示「模型已变更，建议运行金标评测验证」+一键运行入口（F11 的脚本化评测）；
- 金标评测不通过 → 提示回退旧模型（旧配置保留一个备份位）。

## 第四章 架构原则

1. **模块边界**：server（路由壳）/chat（编排）/search（检索）/store（数据）/parser（解析）/ingest（索引）/embeddings（嵌入）/ocr（识别）/export（导出）——单一职责，互不越界；
2. **接口抽象**：嵌入=单函数 `embed()`；向量库=5 函数——「将来换掉它，只改一个文件」是每个外部依赖的验收标准；
3. **数据永不在代码**：API Key 外置（打包时注入、源码仓库无 Key）；语料外置（res/builtin_kb）；配置全部进 settings；**披露义务：用户自填 Key 以明文存本机 settings 文件——《隐私说明》写明「请勿外发配置文件」**；
4. **可回退设计**：本评审表每个选型都有「风险与回退」列——选型评审的产出物就是回退地图；
5. **索引可再生原则**：docs 源文件是唯一事实源，索引任何时候可重建——这使「嵌入模型切换」「存储损坏恢复」都成为可控操作。

## 第六章 PM 知识点卡

**卡 1 ｜ 技术决策的第一原则：服务于产品约束**
- 概念：技术选型评审的第一行永远是「产品约束清单」，候选方案的比较维度来自约束——选型不是选「哪个技术最好」，是选「哪个技术最贴合约束」。
- 业内做法：评审前先列约束（本地私有/低成本/校园网/设备跨度/协作形态），每个候选按约束逐条打分；违背硬约束的一票否决。
- 示例：本评审的约束清单写在文档头部——「校园网不稳」直接否决了需要下载大模型的本地嵌入方案；「非程序员发起人+AI 协作」否决了 Tauri（Rust）；「千元机」否决了 Electron（体积）。每个决定都能回溯到一条产品约束。

**卡 2 ｜ 可回退设计（接口抽象的成本与收益）**
- 概念：每个外部依赖换掉的代价=当初接口抽象的质量。「可回退」不是悲观，是承认技术环境会变（库停更、轮子缺平台、供应商涨价）。
- 业内做法：对外部依赖做最小接口封装（只暴露业务需要的几个函数）；评审时问「明天它坏了，我们要花多久换掉？」——答案超过一周的依赖要重新评估。
- 示例：embed() 单接口+向量库 5 函数——sqlite-vec 打包受阻时「一天内换 numpy」不是吹牛而是接口设计的结果。这是用一点点抽象成本买来的确定性。

**卡 3 ｜ 技术债管理：承认债、记录债、定期还**
- 概念：技术债=「现在求快，将来要还」的取舍。健康团队不怕有债，怕的是债不记账——不知道哪笔债在哪，它会在最坏的时候炸。
- 业内做法：评审时点记录债（在哪、为什么借、什么时候还）；版本规划中留还债空间；债有「利息」（拖越久利息越高——代码越绕改起来越贵）。
- 示例：本产品最大一笔技术债是「引用保真校验（F12/G2）」——现在靠铁律+人工核对兜底，债记在 PRD 观察项里；它的利息=用户每发现一次引用错误就损失一点信任。所以虽然置信度最低，债的「到期日」不能无限推迟。
