# 药鉴 · 数据埋点方案（S6 产出）

> 版本 1.0 ｜ 2026-09-17 ｜ 0→1 流程 S6（指标体系与数据埋点）执行产出
>
> **文档定位**：把 S3 定案的指标（北极星+过程指标链）落成可测量的埋点方案。本方案为**设计文档**，实现属后续开发步骤（需另行拍板）。
>
> **方案拍板（用户 2026-09-17）**：本地埋点 + 用户可导出（否决纯本地不导出、云端埋点——后者违背决策 1 无服务器与本地私有定位）。

---

## 第一章 方案概述

**设计原则**（与「本地私有」定位一致）：
1. **数据归用户**：所有事件只写入本机 SQLite，与聊天数据同库，绝不上传；
2. **用户可见**：设置页「使用数据」面板——用户随时查看自己的使用统计；
3. **用户可控**：可一键导出（JSON/CSV）、可删除；
4. **最小化**：只记行为不记内容——事件流不含提问/回答正文（对话原文仍只存在于用户本机，导出文件不带走）；
5. **为验证服务**：每个事件都对应一个过程指标或假设，拒绝「记了再说」的垃圾事件。

**与 S11 用户测试的衔接**：测试者测试完 → 设置 → 使用数据 → 导出 → 把导出文件发给用户汇总。事件流足以计算全部过程指标，且不含测试者隐私内容。

## 第二章 事件清单（事件 → 指标映射）

> 字段通用：ts（时间）、version（APP 版本）。单条事件含 payload（JSON 属性）。「对应指标/假设」列证明每个事件的必要性。

| 事件名 | 触发时机 | payload 关键字段 | 对应指标/假设 |
|---|---|---|---|
| `app_launch` | APP 启动 | 是否首次启动、主题 | 获取：周新增用户（近似：首次启动计数） |
| `kb_created` | 新建知识库 | kb_id、名称 | 激活：建库行为 |
| `doc_imported` | 文档导入完成 | kb_id、文件数、类型分布、成功/失败数 | 激活：资料导入完成率（P4/H6） |
| `question_asked` | 用户提问（流式开始） | conv_id、kb 范围类型（单/多/全部）、轮次 | 北极星指标基础件；有效会话判定基础 |
| `answer_done` | 回答完成 | conv_id、是否命中、是否拒答、生成耗时、引用条数 | 拒答率；生成质量粗指标 |
| `citation_clicked` | 点击引用徽章 | conv_id、会话内第几次核对、引用序号 | **信任：新用户前 3 次问答引用核对率（H1）**；会话有效性判定 |
| `refusal_followup` | 拒答后 10 分钟内继续提问 | conv_id | 拒答后继续提问率（H2） |
| `note_generated` | 生成知识笔记 | 关键词、勾选模块数、格式（文本/导图）、耗时 | 深度：笔记生成数（H7） |
| `note_saved_to_kb` | 笔记一键入库 | kb_id | 深度：笔记→知识库转化 |
| `card_created` | 生成问答卡 | 卡片数、来源（笔记/手动） | 深度：笔记→卡片转化率（H10） |
| `card_reviewed` | 卡片复习一次 | 卡片数、间隔等级（新/短/中/长） | **深度：卡片复习间隔保持率；北极星指标基础件** |
| `quiz_started` | 进入自测模式（F10 二期） | 题库来源、第几次自测 | 深度：自测使用（H11）；**自测 7 天回访率**基础件 |
| `quiz_completed` | 完成自测会话 | 答题数（全程/中途退出区分） | 深度：**自测完成率**（中途退出率=题烂/体验差信号） |
| `quiz_rated` | 自测结束页内嵌微型问卷（👍/👎 或 1~5 星，无额外界面、可跳过） | 评分 | 深度：**自测有用度**（H11 联动） |
| `quiz_card_rated` | 单题 👍/👎 反馈（题卡下角） | 题编号、👍/👎 | 深度：出题质量反馈（兼作金标出题评测的免费标注数据） |
| `key_replaced` | 用户自填/替换 API Key | — | **付费：自填 Key 率（H8）**（充值发生在百炼控制台无法埋点，此事件为最近似代理指标+测试问卷补足，如实声明） |
| `feedback_submitted` | 提交意见反馈（F15） | 通道（复制/本机/GitHub） | 反馈闭环：反馈量（S11 测试者反馈收集） |
| `events_exported` | 用户导出使用数据 | 事件条数 | 数据回收动作计数 |

**北极星指标的计算口径**（在统计面板与导出摘要中实现）：
> 每周有效学习会话数 = 一周内 conv_id 去重后，满足「该会话内发生**成功回答（answer_done 且命中、非拒答）≥1** 或 note_generated ≥1 或 card_reviewed ≥1 或 quiz_completed ≥1」的会话数。
>
> **口径修正记录（2026-09-17 用户拍板）**：原口径以「点引用」为必要条件——与「引用点击是验证性行为、信任建立后自然下降」自相矛盾（若点击率下降正常，北极星会随信任成熟而系统下降），且把纯问答用户排除在有效使用之外。修正：纯问答（成功回答）即有效；citation_clicked 移出北极星口径，归位信任过程指标（新用户前 3 次核对率）；拒答会话不计入。

**设计纪律（评审修正）**：不埋「答题对/错」——正确率是用户的学习指标不是产品的健康指标（用户答错可能说明题有区分度=产品好）。产品侧只看「用户愿不愿意再来」（回访率）、「能不能做完」（完成率）、「觉得有没有用」（微型问卷/单题反馈）。

## 第三章 存储设计（SQLite）

```
events 表（chat.db 内新建）：
  id        INTEGER PRIMARY KEY
  ts        TEXT（ISO 时间）
  event     TEXT（事件名，白名单约束）
  conv_id   TEXT（可空）
  kb_id     TEXT（可空）
  payload   TEXT（JSON 属性，禁止写入文本内容——导入校验）
  version   TEXT
```

要点：①event 名白名单（只允许第二章 15 种，防事件膨胀）；②payload 写入前校验不含大段文本（长度上限 500 字符）；③与对话/笔记数据同库不同表，删除事件不影响其他数据，反之亦然。

## 第四章 用户界面与回收流程

**设置页新增「使用数据」面板**（实现时加入，与「语料统计」并列）：
1. **统计摘要**：本周有效学习会话数、累计问答/笔记/卡片复习数、引用核对率（新用户口径）——用户看到的产品在用数据「回报」他什么；
2. **导出**：一键导出 `yaojian-usage-YYYYMMDD.json`（事件流）+ `-summary.csv`（按周聚合的指标摘要）——**导出文件不含任何提问/回答/笔记正文**；
3. **删除**：清空本机事件数据（不可恢复，二次确认）。

**S11 用户测试回收流程**（写入测试计划）：
- 测试者完成任务清单后：设置 → 使用数据 → 导出 → 把 JSON 文件发回给用户；
- 用户汇总所有测试者文件 → Claude 聚合计算过程指标 → 对照 H1~H11 判定。

## 第五章 PM 知识点卡

**卡 1 ｜ 行为事件 vs 页面事件**
- 概念：埋点记「行为」不记「页面」——用户做了什么（点了引用、问了题）比看到了什么（打开了设置页）更有决策价值。行为事件能推导漏斗，页面事件只能算 PV（虚荣指标）。
- 业内做法：事件名=过去式动词（question_asked 而非 question_page）；每个事件绑定一个指标，无指标的事件不埋。
- 示例：本方案 15 个事件全部是行为动词（asked/clicked/reviewed/exported），且第二章表格每一行都写了「对应指标/假设」——没有一行是「记了再说」。

**卡 2 ｜ 数据伦理：可见、可控、最小化**
- 概念：埋点的信任成本不亚于收益——用户发现产品偷偷记数据，损失大于指标收益。伦理三原则：用户可见（知道记了什么）、用户可控（可导出可删除）、数据最小化（只记达成目标所需的最少数据）。
- 业内做法：设置页透明展示埋点内容；导出让用户拿回自己的数据；不记内容只记行为。
- 示例：本方案「使用数据」面板=可见；导出/删除=可控；事件流不含问答正文=最小化。这也与「本地私有」定位互为支撑——埋点本身成了产品的信任资产。

**卡 3 ｜ 代理指标与诚实声明**
- 概念：目标行为无法直接测量时用「代理指标」近似，但必须写明近似关系与误差方向，否则会误导决策。
- 业内做法：付费埋点=「自填 Key 率」是「付费意愿」的代理——自填 Key 的人大概率愿意付费，但愿意付费的人不一定自填 Key（可能用内置 Key）。代理指标用于信号判断，不用于精确统计。
- 示例：`key_replaced` 事件与 H8 的关系在第二章如实声明「充值发生在百炼控制台无法埋点，此事件为最近似代理+测试问卷补足」——不用代理指标冒充精确数据。
